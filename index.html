KNOWLEDGE BASE / DATA COLLECTION

Como exportar logs

Guias de coleta para preparar arquivos compatíveis com o Security Log Analysis. Selecione a origem, siga as etapas e depois abra Analisar logs. Não é necessário Excel para coletar logs.

Antes de começar: faça coletas apenas em sistemas sob sua autorização. Registros podem conter nomes, IPs, caminhos, tokens e dados pessoais. Esta interface não envia arquivos ao servidor, mas arquivos que você baixar ou compartilhar exigem proteção. Preserve o original e, se possível, seu SHA-256 antes de transformar os dados.
WINDOWS EVENT LOGS

Exportar eventos do Windows

Recomendado: exportar como CSV usando PowerShell. O formato EVTX original é útil para preservação forense, mas não é interpretado diretamente pelo analisador atual.

Opção A — PowerShell (CSV pronto para importar)

  1. Abra o menu Iniciar, pesquise PowerShell e execute como administrador.
  2. Copie o comando abaixo para exportar até 200 eventos do log Security nas últimas 24 horas.
  3. Procure WindowsSecurity.csv na pasta SecurityLogAnalysis da sua área de trabalho.
  4. No menu Analisar logs, selecione o CSV e filtre por mensagem, host ou severidade.
# PowerShell — exportação CSV (últimas 24 horas)
$saida = Join-Path $env:USERPROFILE 'Desktop\SecurityLogAnalysis'
New-Item -ItemType Directory -Path $saida -Force | Out-Null
$eventos = Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    StartTime = (Get-Date).AddDays(-1)
} -MaxEvents 200 -ErrorAction Stop
$eventos | ForEach-Object {
    [PSCustomObject]@{
        timestamp = $_.TimeCreated.ToString('yyyy-MM-dd HH:mm:ss')
        source    = 'Windows Security'
        src_ip    = ''
        host      = $_.MachineName
        event     = "Event ID $($_.Id): $($_.Message -replace '[\r\n]+',' ')"
        severity  = if ($_.Id -in @(4625,4740,1102)) {'high'} else {'low'}
    }
} | Export-Csv -Path (Join-Path $saida 'WindowsSecurity.csv') -NoTypeInformation -Encoding UTF8

Se o PowerShell não encontrar eventos, aumente a janela de tempo; se faltar permissão, verifique as políticas da máquina. A coluna src_ip foi deixada vazia porque a origem não está presente em todos os eventos; nunca preencha um IP por suposição.

Opção B — Visualizador de Eventos

  1. Execute eventvwr.msc e abra Logs do Windows → Segurança.
  2. Use Filtrar Log Atual para selecionar período e IDs.
  3. Use Salvar Todos os Eventos Como... para preservar o arquivo EVTX original.
  4. Para analisar no site, converta/exporte para CSV estruturado, por exemplo usando o PowerShell acima.

NETWORK SECURITY

FortiGate / FortiAnalyzer

Os nomes das opções mudam conforme a versão do FortiOS, FortiAnalyzer e permissões da conta.

Exportação pela interface

  1. Acesse o FortiGate ou FortiAnalyzer com uma conta autorizada.
  2. No FortiGate, abra Log & Report e selecione uma categoria, como Forward Traffic, Local Traffic ou Security Events (se disponível).
  3. No FortiAnalyzer, utilize a visualização de logs correspondente à unidade e categoria desejadas.
  4. Defina o intervalo e filtre por IP de origem/destino, ação (accept/deny), política ou porta.
  5. Utilize a opção de download/exportação disponível para gerar CSV ou texto. Se não estiver disponível, isso pode depender de versão, licença ou perfil de acesso.
  6. Importe o arquivo na plataforma e confira se os campos foram reconhecidos corretamente.

Exemplo de formato de log bruto

date=2026-11-10 time=14:00:10 devname="FW-LAB" type="traffic" subtype="forward" srcip=192.0.2.10 dstip=198.51.100.20 dstport=443 action="deny" policyid=7
Arquivo recomendado: CSV com colunas timestamp,source,src_ip,host,event,severity ou logs key=value após validação do parser. No analisador atual, registros proprietários podem aparecer como texto simples e exigir adaptação.

O que observar?

Origem e destino, portas, política, interface, bytes, sessão, direção, timezone e a distinção entre tráfego bloqueado e ameaça confirmada.

HOST DETECTION

Wazuh

Opção A — Dashboard

  1. Abra o Wazuh Dashboard com permissão para consulta.
  2. Entre na área de eventos/alertas da instalação.
  3. Filtre intervalo, agente, regra, severidade e índices relevantes.
  4. Quando houver opção, exporte os resultados em JSON ou CSV. Disponibilidade varia com a versão e interface.
  5. Importe o arquivo e valide os campos de cada alerta.

Opção B — Alertas em JSON (servidor Linux, com autorização)

Em muitas instalações o arquivo de alertas estruturados fica em /var/ossec/logs/alerts/alerts.json. Cada linha normalmente contém um objeto JSON.

# No servidor Wazuh, copiar uma amostra para laboratório autorizado
sudo tail -n 200 /var/ossec/logs/alerts/alerts.json > wazuh-alerts-demo.jsonl

Extensão recomendada: .jsonl (um JSON por linha). Na interface, procure timestamp, rule.level, rule.description, agent.name, data.srcip e full_log. Faça anonimização antes de compartilhar.

Interpretação

Um alerta de alta severidade indica prioridade de investigação, não comprometimento confirmado. Verifique o evento bruto, histórico do agente, correlação e possíveis falsos positivos.

NETWORK DETECTION & RESPONSE

NDR

Cada NDR possui menus e esquemas diferentes. Este roteiro é independente de fabricante.

Exportar alertas ou fluxos

  1. Entre no console NDR e localize Detections / Alerts / Events / Network Flows, conforme a ferramenta.
  2. Selecione o período e os ativos sob investigação.
  3. Filtre por IP, DNS, protocolo, porta, assinatura ou tipo de anomalia.
  4. Exporte em CSV ou JSON, caso haja suporte.
  5. Antes da importação, confira se existe pelo menos horário, fonte, IP/host e descrição do evento.
  6. Se o formato não for reconhecido, mapeie os campos para o padrão CSV descrito na guia Excel/CSV.

Exemplo de registro para teste

timestamp,source,src_ip,host,event,severity
2026-11-10 14:10:00,NDR,192.0.2.20,LAB-PC-01,Unusual DNS volume,medium
Telemetria de fluxo não equivale a captura integral de pacotes. Um alerta de anomalia não comprova C2 ou exfiltração sem outras evidências.
LINUX / SYSTEM LOGS

Linux

Comandos para hosts Linux autorizados, com systemd. O nome do serviço e os caminhos variam conforme a distribuição.

Opção A — journalctl

  1. Abra o terminal no host ou VM de laboratório.
  2. Confirme o período e o serviço que deseja investigar.
  3. Exporte os registros de SSH em texto com o comando abaixo.
  4. Importe o arquivo ssh-logs.txt. Logs em texto simples podem exigir interpretação manual adicional.
# Ajuste a data e o nome do serviço (ssh ou sshd)
sudo journalctl -u ssh --since "2026-11-10 00:00:00" --until "2026-11-11 00:00:00" -o short-iso --no-pager > ssh-logs.txt

Opção B — arquivos de autenticação

# Debian / Ubuntu (se o arquivo existir)
sudo grep -Ei 'Failed password|Accepted|Invalid user' /var/log/auth.log > ssh-auth-filtered.txt

# RHEL / derivados (se o arquivo existir)
sudo grep -Ei 'Failed password|Accepted|Invalid user' /var/log/secure > ssh-auth-filtered.txt
Para obter melhor filtragem e correlação, transforme os eventos em CSV estruturado com timezone, host e origem. Preserve sempre o arquivo original; não altere evidências primárias.
STRUCTURED DATA / CSV

Excel / CSV

Excel é opcional: serve para preparar logs ou revisar colunas. O site não aceita .xlsx diretamente.

  1. Crie uma planilha com o cabeçalho abaixo.
  2. Preencha uma linha por evento, sem mesclar células.
  3. Utilize datas com horário claro e anote o timezone original no relatório.
  4. Em Arquivo → Salvar como, selecione CSV UTF-8.
  5. Importe o CSV na aba Analisar logs. A versão do analisador deve ser conferida quanto ao separador aceito; o exemplo abaixo usa vírgulas.
timestamp,source,src_ip,host,event,severity
2026-11-10 14:30:00,Windows Security,192.0.2.10,LAB-PC-01,Event ID 4625: Failed logon,high
2026-11-10 14:31:00,Firewall,192.0.2.20,FW-LAB,Connection denied,medium
2026-11-10 14:32:00,NDR,192.0.2.30,LAB-SRV-01,Unusual traffic,medium

Os endereços 192.0.2.0/24 e 198.51.100.0/24 são exemplos reservados para documentação. Não são IPs de ameaças reais.
